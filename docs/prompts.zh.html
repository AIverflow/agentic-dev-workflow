🧒 简单讲解（ELI5）

遇到难懂的主题时使用。智能体用大白话解释，然后检查你是否听懂了。

需要填写：[主题]

用最简单的话，向一个完全的新手解释[主题]，就像在对五岁小孩讲。
- 最多 150 字（不含问题）。短句。不用术语；如果少不了某个术语，用 5 个字以内解释它。
- 先用一个日常类比开头（厨房、邮局等），然后用一句话说明这个类比在哪里不再适用。
- 然后给一个具体例子，用真实的数值。
- 最后以这句话结束："需要记住的一件事：……"（一句话）。
- 然后问我 2 个问题，检查我是否听懂了，并等待。不要自己回答。
  我回答后，用 1–2 句话纠正每个答案。

🖼️ 用图示讲解

当某个主题、问题或流程难懂时使用。智能体会生成一个带图示的 HTML 页面。

需要填写：[主题 / 问题 / 工作流] [受众]

把 [主题 / 问题 / 工作流] 做成一个独立的 HTML 页面来教我。
重点是理解，而不是装饰。

首先：如果主题或受众不明确，最多问我 3 个问题，然后等待。

受众：[大学毕业生 | 初级开发者 | 非技术人员]。
用大白话，按这个水平解释事物本身。
对于这个受众可能不懂的每个术语，第一次出现时用不超过 8 个字给出定义。
受众已经懂的术语不用定义。

页面结构，按以下顺序：
1. 标题，然后一句话的答案：它是什么，或问题是什么。
2. 为什么重要：一句话说明没有它会出什么问题。
3. 图示（主要部分）。最多 10 个方框，标签最多 4 个词。
   - 按阅读顺序给步骤编号 1、2、3。
   - 每个角色或组件用一种颜色，并附一个小图例。
     判断用菱形；循环用回指的箭头。
   - 图示下方，每个编号步骤用一句大白话说明：发生了什么，以及为什么。
4. 一个带真实数值的完整例子，按编号步骤走一遍。
5. 常见错误：最多 3 条要点。
6. "记住"：一句话。

技术规则：
- 一个文件，内联 <style>。不使用外部资源，不使用 CDN，不使用框架；
  可以离线通过 file:// 打开。
- 用 CSS grid 排列图示中的方框；箭头保持简单（CSS 或小的 SVG 线条）。
  不得重叠，文字不得溢出方框。
  如果能在浏览器中打开页面，完成前请检查。
- 宽度小于 600px 时，图示从上到下堆叠。打印时可读。
- 颜色用 :root 中的 CSS 变量定义。
- 短句。没有废话。结构之外不要添加任何内容。

保存为 [主题名称].html。

🗺️ 带我了解这个仓库

打开一个你还不熟悉的项目时使用。智能体会阅读代码（不做任何修改），给你一张地图、一个真实的例子，以及应该先读什么。

需要填写：[区域]

带我了解这个仓库的 [区域]。我是新来的。只读：不要改动任何东西。

1. 用 3 句话说明：这个项目做什么，谁在用它。
2. 技术栈：编程语言、框架，以及如何运行它和它的测试。
3. 地图：最多 8 个主要文件夹或模块，每个用一行说明它负责什么。
4. 一个真实的例子：选一个常见操作（一次点击、一个请求、一条命令），沿着代码一步一步走一遍，并附上文件路径。
5. 最容易踩的 3 个坑：在我第一次改动之前，会让我感到意外的事情。
6. 接下来读什么：我应该先读的 5 个文件，按顺序排列，每个用一行说明原因。

规则：
- 大白话，短句。给出初级开发者可能不懂的术语的解释。
- 指向真实存在的文件（path:line）。不要猜：不确定时，就直接说明。
- 然后问我想改什么，并等待。

📦 交接到一个全新的会话

会话变长、智能体开始忘记事情，或某一步完成时使用。智能体写一份简短的笔记，然后新会话读取它，接着继续工作。

无需填写。在新会话中说：读取 handoff.md，然后继续。

我们要结束这个会话了。请写一份交接笔记，让一个没有这次聊天记忆的新智能体能够接着完成工作。把它保存为 handoff.md。

按以下顺序列出各部分：
1. 目标：我们在构建什么，用 2 句话说明。
2. 决策：我们选了什么、为什么，每条一行。也要写上我们否决的选项，免得有人重新讨论。
3. 已完成：已经做完且能正常工作的内容（附文件路径）。
4. 未完成：剩下的内容，按顺序排列，最小的下一步放在最前面。
5. 待定问题：我还需要决定的任何事情。
6. 注意：我们踩过的坑，以及看起来对但其实错了的事情。
7. 先读：新智能体应该打开的文件，每个用一行说明原因。

规则：
- 最多 60 行。只写事实，不要讲聊天的经过。
- 指向文件和提交，不要粘贴代码。
- 现在不要改动任何代码。
- 完成后把笔记给我看，这样我可以在切换前修改。

🎟️ 并行创建工单

想一次做很多工单时使用。一个总控智能体负责规划、审查和提交，辅助智能体负责写代码。

需要填写：工单 基础分支 最多并行工单数

你是负责构建一组工单的**总控（orchestrator）**。
你负责规划、分派工作、审查和提交。辅助子智能体负责写代码。

## 输入（请填写这些内容）

- **工单：**<文件夹或 spec 的路径、issue 编号或链接，或粘贴的清单>
- **基础分支：**<例如 main>
- **最多并行工单数：**<默认 3>

## 基本规则

- 我来做决定。遇到产品或设计问题，绝不要猜：问我。
- 遵循仓库的 `AGENTS.md` / `CLAUDE.md`、编码规范和提交约定。
- 给辅助智能体**指针**，不要给副本：工单路径或链接、spec 路径、相关文件。
- 除非我说可以，否则不要推送、开 PR 或关闭工单。
- 所有人在同一个文件夹里、同一个分支上工作。只有两个工单改的是**不同的文件**，才能同时进行。否则，一个接一个地做。
- 如果无法并行运行子智能体，就一次只做一个工单。

## 第 1 步：先规划，等我同意

1. 读完每一个工单、它的 spec，以及仓库的术语表和编码规范（如果有）。
2. 找到类型检查、lint、单个测试文件和完整测试套件的命令。
3. 给我看：
   - 一张表：工单、被谁阻塞（猜测的标注"推断"）、可能会改动的文件
   - 第一批：没有未完成阻塞项、也没有共享文件的工单
   - 待定问题，每个都附上你推荐的答案
4. 从基础分支创建分支 `tickets/<short-name>`。
5. **停下。等待我的同意和回答。**

## 第 2 步：循环，逐个处理每个工单

1. **构建**（实现子智能体）：
   - 先写测试：为一个小行为写一个失败的测试，然后只写刚好能让它通过的代码。重复这一过程。如果装了 `tdd` skill，就使用它。
   - 只修改为本工单规划的文件。如果需要其他文件，停下来问总控。
   - 只做本工单范围内的事。不要顺手重构。不要提交。
   - 遇到阻塞性问题（需求不清楚、有两种都合理的设计、范围必须扩大）？停下来，把问题连同选项和推荐方案一起报告。不要猜。
   - 报告：改动的文件、测试结果、疑虑。
2. **审查**（单独的审查子智能体，绝不能是实现者本人）：
   - 阅读工单，以及它所涉文件的差异。如果装了 `code-review` skill，就使用它。
   - **Spec：**是否完成了工单要求的全部内容，且没有多做？
   - **Standards：**是否遵循仓库的规则？是否简单、清楚？
   - 按重要性从高到低报告发现的问题。不要修复任何内容。
3. **修复**：把发现的问题交回实现者。**最多修复 2 轮**，之后问我。
4. **提交**：运行完整测试套件。全部通过，就只提交本工单的文件，提交信息要写明工单名。失败，就退回第 1 步。
5. **下一步**：把工单标记为完成（对于本地文件，设置 `Status: done`），然后开始现在已解除阻塞的工单。

### 何时问我

- 被阻塞的工单等待；其他工单继续。把问题**一次性**发给我：工单、问题、选项、你的推荐。
- 出现以下情况，就停下一切并问我：重试一次后测试仍然失败，某个工单两次审查不通过，或两个工单互相矛盾。
- 每次提交后，发一行状态：已完成、进行中、被阻塞。

## 第 3 步：收尾

1. 最后再运行一次完整测试套件和类型检查。
2. 对照基础分支，审查整个分支（Spec 和 Standards）。
3. 修复你和我都同意修复的内容。
4. 给我一张表：工单、测试、审查发现、修复轮次、提出的问题。列出值得单独开后续工单的事项。
5. 让分支处于可供我审阅和合并的状态。

让智能体来写提示词

面对大任务，不要自己写提示词。把各个部分交给智能体（目标、背景、规则、何时算完成），让它写出真正的提示词。

📝 就像告诉朋友你需要什么，他替你写邮件。发送前，你仍然要先读一遍。

✍️ 帮我写一段提示词

任务很大，或者你会反复使用这段提示词时使用。读一遍结果，改正错误，然后粘贴到一个全新的会话中。

需要填写：[目标] [背景] [必须做] [不能做] [何时算完成]

请为一个编程智能体写一段提示词。不要自己做这个任务。

目标：[目标]
背景：[背景：项目、文件、给谁用]
必须做：[必须做]
不能做：[不能做]
何时算完成：[何时算完成]

首先：请问我最多 5 个问题，关于缺少或不清楚的内容，然后等待。

然后写出提示词：
- 面向一个没有这次聊天记忆的智能体：放入它需要的全部内容。
- 清晰的步骤，按顺序。短句，简单词语。
- 说明在哪里停下来问我，以及最后要向我汇报什么。
- 每次需要我填写的内容，用 [方括号] 标出。
- 最多 40 行。删掉智能体本来就会做的内容。

把它放在一个代码块里展示，然后列出 3 种它可能出错的方式。
💡

提示：智能体擅长搭结构，你清楚目标。一定要读一遍它写出的提示词：如果里面有错误，智能体每次都会重复这个错误。

基于 Matt Pocock 的 skills，适用于编程智能体。 内容对应 1.3.1 版本（2026 年 10 月）。 在命令菜单中，skill 可能带有前缀显示，例如 /mattpocock-skills:grill-with-docs。
