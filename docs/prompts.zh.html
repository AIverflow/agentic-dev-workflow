🧒 简单讲解（ELI5）

遇到难懂的主题时使用。智能体用大白话解释，然后检查你是否听懂了。

需要填写：[主题] [我已经知道的]

用最简单的话，向一个完全的新手解释[主题]，就像在对五岁小孩讲。
我已经知道的：[我已经知道的，例如"我用 git，但没听说过 rebase"]。
- 最多 150 字（不含问题）。短句。不用术语；如果少不了某个术语，用 5 个字以内解释它。
- 先用一个日常类比开头（厨房、邮局等），然后用一句话说明这个类比在哪里不再适用。
- 然后给一个具体例子，用真实的数值。
- 最后以这句话结束："需要记住的一件事：……"（一句话）。
- 然后问我 2 个问题，检查我是否听懂了，并等待。不要自己回答。
  我回答后，用 1–2 句话纠正每个答案。

🖼️ 用图示讲解

当某个主题、问题或流程难懂时使用。智能体会生成一个带图示的 HTML 页面。

需要填写：[主题 / 问题 / 工作流] [受众]

把 [主题 / 问题 / 工作流] 做成一个独立的 HTML 页面来教我。
重点是理解，而不是装饰。

首先：如果主题或受众不明确，最多问我 3 个问题，然后等待。

受众：[受众：大学毕业生 | 初级开发者 | 非技术人员]。
用大白话，按这个水平解释事物本身。
对于这个受众可能不懂的每个术语，第一次出现时用不超过 8 个字给出定义。
受众已经懂的术语不用定义。

页面结构，按以下顺序：
1. 标题，然后一句话的答案：它是什么，或问题是什么。
2. 为什么重要：一句话说明没有它会出什么问题。
3. 图示（主要部分）。最多 10 个方框，标签最多 4 个词。
   - 按阅读顺序给步骤编号 1、2、3。
   - 每个角色或组件用一种颜色，并附一个小图例。
     判断用菱形；循环用回指的箭头。
   - 图示下方，每个编号步骤用一句大白话说明：发生了什么，以及为什么。
4. 一个带真实数值的完整例子，按编号步骤走一遍。
   如果这个项目里有真实的案例，就用它。
5. 常见错误：最多 3 条要点。
6. "记住"：一句话。

技术规则：
- 一个文件，内联 <style>。不使用外部资源，不使用 CDN，不使用框架；
  可以离线通过 file:// 打开。
- 用 CSS grid 排列图示中的方框；箭头保持简单（CSS 或小的 SVG 线条）。
  不得重叠，文字不得溢出方框。
  如果能在浏览器中打开页面，完成前请检查。
- 宽度小于 600px 时，图示从上到下堆叠。打印时可读。
- 颜色用 :root 中的 CSS 变量定义。
- 短句。没有废话。结构之外不要添加任何内容。

保存为 [主题名称].html。

🗺️ 带我了解这个仓库

打开一个你还不熟悉的项目时使用。智能体会阅读代码（不做任何修改），给你一张地图、一个真实的例子，以及应该先读什么。

需要填写：[区域]

带我了解这个仓库的 [区域，或"整个仓库"]。我是新来的。只读：不要改动任何东西。

1. 用 3 句话说明：这个项目做什么，谁在用它。
2. 技术栈：编程语言、框架，以及如何运行它和它的测试。
3. 地图：最多 8 个主要文件夹或模块，每个用一行说明它负责什么。
4. 一个真实的例子：选一个常见操作（一次点击、一个请求、一条命令），
   沿着代码一步一步走一遍，并附上文件路径。
5. 最容易踩的 3 个坑：在我第一次改动之前，会让我感到意外的事情。
6. 接下来读什么：我应该先读的 5 个文件，按顺序排列，每个用一行说明原因。

规则：
- 最多 80 行。
- 大白话，短句。给出初级开发者可能不懂的术语的解释。
- 指向真实存在的文件（path:line）。不要猜：不确定时，就直接说明。
- 然后问我想改什么，并等待。
✍️

让智能体来写提示词

面对大任务，不要自己写提示词。把各个部分交给智能体（目标、背景、规则、何时算完成），让它写出真正的提示词。

📝 就像告诉朋友你需要什么，他替你写邮件。发送前，你仍然要先读一遍。

✍️ 帮我写一段提示词

任务很大，或者你会反复使用这段提示词时使用。读一遍结果，改正错误，然后粘贴到一个全新的会话中。

需要填写：[目标] [背景] [必须做] [不能做] [何时算完成]

请为一个编程智能体写一段提示词。不要自己做这个任务。

目标：[目标]
背景：[背景：项目、文件、给谁用]
必须做：[必须做]
不能做：[不能做]
何时算完成：[何时算完成]

首先：读你需要的文件。然后最多问我 5 个问题，只问代码本身告诉不了你的内容，
然后等待。

然后写出提示词：
- 面向一个没有这次聊天记忆的智能体：放入它需要的全部内容。
- 清晰的步骤，按顺序。短句，简单词语。
- 说明在哪里停下来问我，以及最后要向我汇报什么。
- 每次需要我填写的内容，用 [方括号] 标出。
- 最多 40 行。删掉智能体本来就会做的内容。

列出 3 种它可能出错的方式，针对每一种修改提示词，最后把它放在一个代码块里展示。
💡

提示：智能体擅长搭结构，你清楚目标。一定要读一遍它写出的提示词：如果里面有错误，智能体每次都会重复这个错误。
