Ready-to-use prompts

Copy a prompt, fill in the blanks, and paste it into a fresh agent session.

🧒 Explain it simply (ELI5)

Use it when a topic feels hard. The agent explains it in plain words, then checks that you understood.

Fill in: [TOPIC] [WHAT I KNOW]

Explain [TOPIC] to a complete beginner, like I'm 5.
What I already know: [WHAT I KNOW, e.g. "I use git but never heard of rebase"].
- Max 150 words (not counting the questions). Short sentences. No jargon; if a term is unavoidable, define it in 5 words.
- Start with one everyday analogy (kitchen, post office, etc.), then one sentence on where the analogy breaks.
- Then one concrete example with real values.
- End with: "The one thing to remember: ..." (one sentence).
- Then ask me 2 questions to check I understood, and wait. Don't answer them yourself.
  When I reply, correct each answer in 1–2 sentences.

🖼️ Teach it with a diagram

Use it when a topic, problem or workflow is hard to understand. The agent builds one HTML page with a diagram.

Fill in: [TOPIC / PROBLEM / WORKFLOW] [AUDIENCE]

Teach me [TOPIC / PROBLEM / WORKFLOW] as one self-contained HTML page.
The goal is understanding, not decoration.

First: if the topic or audience is ambiguous, ask me up to 3 questions and wait.

Audience: [AUDIENCE: college grad | junior dev | non-technical].
Explain the thing itself, in plain words, at that level.
Define every term this audience may not know, the first time it appears,
in under 8 words. Skip definitions for terms they already know.

Page structure, in this order:
1. Title, then a one-sentence answer: what it is, or what the problem is.
2. Why it matters: one sentence on what goes wrong without it.
3. The diagram (main part). Max 10 boxes, labels max 4 words.
   - Number the steps 1, 2, 3 in reading order.
   - One color per actor or component, with a small legend.
     Decisions are diamonds; loops are arrows going back.
   - Under the diagram, one plain sentence per numbered step: what happens and why.
4. One worked example with real values, walked through the numbered steps.
   If this project has a real case, use it.
5. Common mistakes: max 3 bullets.
6. "Remember": one sentence.

Technical rules:
- ONE file, inline <style>. No external assets, no CDN, no framework;
  works offline from file://.
- Lay out the diagram's boxes with CSS grid; keep arrows simple (CSS or small
  SVG lines). Nothing may overlap, and no text may overflow its box.
  If you can open the page in a browser, check this before finishing.
- Under 600px wide, the diagram stacks top to bottom. Readable in print.
- Colors as CSS variables in :root.
- Short sentences. No filler. Nothing outside the structure above.

Save as [topic-name].html.

🗺️ Walk me through this repo

Use it when you open a project you don't know yet. The agent reads the code (no edits) and gives you a map, one real example, and what to read first.

Fill in: [AREA]

Walk me through [AREA, or "the whole repo"] of this repo. I am new here. Read only: don't edit anything.

1. In 3 sentences: what this project does and who uses it.
2. The stack: language, framework, and how to run it and its tests.
3. The map: max 8 main folders or modules, one line each on what it owns.
4. One real example: pick one common action (a click, a request, a command)
   and follow it step by step through the code, with file paths.
5. The top 3 gotchas: things that would surprise me before my first change.
6. Read next: the 5 files I should read first, in order, with one line on why.

Rules:
- Max 80 lines.
- Plain words, short sentences. Define any term a junior dev may not know.
- Point to real files (path:line). Don't guess: if you're not sure, say so.
- Then ask me what I want to change, and wait.
✍️

Let the agent write the prompt

For a big task, don't write the prompt yourself. Give the agent the pieces (goal, context, rules, when it's done) and ask it to write the real prompt.

📝 Like telling a friend what you need, and they write the email for you. You still read it before you hit send.

✍️ Write a prompt for me

Use it when a task is big or you'll reuse the prompt. Read the result, fix it, then paste it into a fresh session.

Fill in: [GOAL] [CONTEXT] [MUST] [MUST NOT] [DONE WHEN]

Write a prompt for a coding agent. Don't do the task yourself.

Goal: [GOAL]
Context: [CONTEXT: project, files, who it's for]
Must: [MUST]
Must not: [MUST NOT]
Done when: [DONE WHEN]

First: read the files you need. Then ask me up to 5 questions, only on what the code
can't tell you, and wait.

Then write the prompt:
- For an agent with no memory of this chat: put in all it needs.
- Clear steps, in order. Short sentences, plain words.
- Say where to stop and ask me, and what to report at the end.
- Use [BRACKETS] for anything I should fill in each time.
- Max 40 lines. Cut anything the agent would do anyway.

List 3 ways it could go wrong, fix the prompt for each, then show it in one code block.
💡

Tip: the agent is good at structure, you know the goal. Always read the prompt it writes: if it has a mistake, the agent will repeat it every time.
